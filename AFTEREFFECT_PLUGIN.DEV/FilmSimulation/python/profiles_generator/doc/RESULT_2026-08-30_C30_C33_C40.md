## 1. C30/C33 — the renderer had its own square root

`film::FilmGrainSigma()` in the generated header is the one definition of grain amplitude and has
been audited against `film_profiles.grain_sigma()` on every build. **Nothing called it.**
`AlgoAddGrain` inlined

```cpp
amp = sqrt(max(D - dmin, 0) + fog)
```

which at NET density 1.0 returns `sqrt(1 + fog_grain)` instead of 1.0. Since **all 161 stocks carry
`fog_grain > 0`**, every frame the plugin rendered was louder than the reference by that factor:

| | |
|---|---:|
| range across the database | **1.0392 – 1.1832** |
| mean | **1.1013** |
| stocks over 5 % | **158 of 161** |

`rms_granularity` is stored at the convention Kodak prints — *"Read at a NET diffuse visual density
of 1.0, using a 48-micrometre aperture"* (5248 p1, 5222 p1). While the stage returned
`sqrt(1 + fog)` there, that stored figure did not mean the number on the sheet.

The second half was structural. The signature took a loose `fogGrain` value, so the stage **could
not reach the measured `sigma(D)` anchors at all** — reaching them needs the `GrainSpec` and the
per-channel `dmax`. A signature that cannot express the law is not an oversight that fixes itself.

**What changed.** `AlgoAddGrain` now takes `dmin[3]`, `dmax[3]` and `const film::GrainSpec&`.
The law moved into one shared place — `AlgoGrainAmpBuild()` / `AlgoGrainAmpAt()` in `AlgoGrain.hpp`
— and both twins call it.

⚠ **Why a hoisted evaluator rather than calling `FilmGrainSigma` per pixel.** That function builds
and insertion-sorts up to four anchors and walks them twice, none of which depends on the pixel.
Per pixel it would be correct and unusable. `AlgoGrainAmpBuild` does that once per channel in
`HighPrecType` and folds the net-1.0 reference into the segment coefficients; the inner loop is left
with one square root and one multiply on the legacy branch, or at most three compares and one FMA on
the measured branch.

## 2. ⚠ The asymmetry that was nearly introduced, and was not

Stages 13 (duplication) and 14 (print) also call this weighting — and the reference renderer does
**not** normalise them:

```python
amp = np.sqrt(np.maximum(out[:, :, c] - final_curves[c].dmin, 0.0) + 0.15)
```

Print and dupe stocks carry **no published rms** to be pinned to; the stock's `grain_rms` is the
field's own amplitude and this weighting is a look, not a calibration. Pinning them would have moved
every print render away from the reference for no measurement's sake — the same class of error as
the one being fixed, in the opposite direction.

So there are two entry points, and the difference is documented at both: `AlgoAddGrain` (pinned,
camera negative) and **`AlgoAddGrainRaw`** (unpinned, print and dupe). `cpp_parity`'s twin check now
requires *both* names in both twins, so the distinction cannot be quietly collapsed.

## 3. C40 — the guard existed in one language

`AlgoSpectralMonoWeights()` had no peak test and no out-of-reach test. It derived collapse weights
for any stock carrying `log_s_pan`, so `KONICA_INFRARED_750` rendered in the **plugin** at
`(0.1611, 0.1931, 0.6458)` — blue-dominant — against the authored and correct red-dominant
`(0.55, 0.15, 0.30)`. An infrared film with its red record effectively gone.

Both tests are now ported, and both read the curve's **own stored samples** rather than the
360–730 nm render grid, for the reason recorded on 2026-08-29: measuring "how much lies outside the
grid" *using the grid* is a threshold compared against a quantity that cannot reach it. On the
clipped grid this stock reads peak 730 nm / 0.203 out of reach; on its own samples, 750 nm / 0.437.

⚠ **`ROLLEI_INFRARED_400` is still not refused, and the threshold must not be tuned to catch it.**
Its stored curve is the *unfiltered* sensitisation — peak 410 nm, 0.028 of its energy past 700 nm —
so by the data on file it is an ordinary panchromatic emulsion. Its authored red-dominant triple
encodes an assumed IR taking filter that no field records. That is **C39**, a carrier, not a
threshold; lowering `ALGO_SPECTRAL_OUT_OF_REACH_MAX` to catch it would start refusing Tri-X.

`--allow-guard-gap` has been **removed** from the build registration rather than left in as a safety
net: a re-opened gap now fails the build instead of printing a line somebody has learned to skip.

## 4. ⚠ What this does to the picture

**Every stock, all densities:** grain amplitude drops by the factor it was wrong by — **1/1.0392 to
1/1.1832**, i.e. **3.9 % to 15.5 % quieter**, mean 9.2 %. Uniform per stock, identical in all three
channels, shape untouched.

**The 13 stocks with a measured `sigma(D)` shape now render that shape instead of a square root,**
and this is not a small correction:

| | shadows (net 0.2) | highlights (net 2.5) |
|---|---:|---:|
| `KODAK_VISION_500T_5279` | **×2.82** | ×0.37 |
| `EASTMAN_EXR_50D_5245` | ×2.70 | ×0.50 |
| `KODAK_VISION3_500T_5219` | ×2.56 | ×0.39 |
| all 13, range | ×1.41 – ×2.82 | ×0.37 – ×0.61 |

Grain rises steeply in the shadows and falls away in the highlights, which is what the granularity
plots on those sheets actually show and what the square root could never produce. **A colourist who
knows these stocks will see the difference immediately.** It is a correction, not a refinement, and
it is the one the owner asked for by choosing "level + measured anchor".

## 5. Single-thread performance, measured, not estimated

Isolated benchmark of `AlgoAddGrain` alone — 1920×1080, three planes, best of 12, pinned to one
core, old and new loops compiled into the same binary and run on the same buffers.

**Scalar (`AlgoType = double`)**

| stock | branch | before | after | |
|---|---|---:|---:|---:|
| `AGFA_APX_25` | legacy | 2.253 ns/px | 2.489 ns/px | **+10.5 %** |
| `EASTMAN_EXR_50D_5245` | measured | 2.239 ns/px | 2.129 ns/px | **−4.9 %** |

**AVX2 (`AlgoType = float`)** — the "before" here is the previous *intrinsic* loop, not a scalar
stand-in, so this is like for like.

| stock | branch | before | after | |
|---|---|---:|---:|---:|
| `AGFA_APX_25` | legacy | 0.817 ns/px | 0.834 ns/px | **+2.1 %** |
| `EASTMAN_EXR_50D_5245` | measured | 0.757 ns/px | 1.010 ns/px | **+33.5 %** |

⚠ **The +33.5 % is not a regression on equal work.** The old measured-branch figure is the cost of
computing the *wrong* answer — the legacy square root on a stock that has a traced shape. There was
no correct measured branch to compare against. The honest reading is: the traced shape costs
0.25 ns/px more than the square root it replaces, on 13 of 161 stocks.

At 1920×1080 the legacy-branch cost is **+1.47 ms/frame scalar** and **+0.11 ms/frame AVX2**, on a
stage whose add is a minority of stage 11's own 7 % share of the frame. One extra multiply per
pixel, which is exactly what the net-1.0 pin is.

End to end, both engines run clean: **scalar PASS 0 failures over 161 stocks**, **AVX2 PASS 0
failures over 161 stocks**.

## 6. The audits changed, and one of them changed in a way worth arguing with

**`cpp_parity.py` — the twin-law token was re-pointed, not removed.** It required `ampScale` in both
twins. That was the right test while the normalisation was a loose local duplicated in two files, and
it did its job: it is what reported, on every build, that the law had gone missing from both sides.
The law now lives in one shared header, so the test asserts both twins call
`AlgoGrainAmpBuild` and `AlgoGrainAmpRaw`.

**⚠ `FilmGrainSigma` left `LAW_BYPASS_BASELINE`, and the reachability check had to grow a concept
to let it.** The stage reaches the law through a hoisted evaluator rather than by calling it, so a
symbol grep still finds nothing. Declaring that as "reached" on my own say-so would be exactly the
kind of convenient reinterpretation the baseline dict warns against. So the indirection is declared
in a new `LAW_EQUIVALENT_IMPL` registry **and licensed by a numeric assertion**: the probe evaluates
`film::FilmGrainSigma()` and the stage's own evaluator **inside the same compiled program, on the
same rows**, and fails if they differ by more than 1e-6. Measured: **2.40e-07**.

**The two-population split in the stage probe is retired.** It used to judge the legacy stocks
exactly and pin the measured-shape gap at "no worse than 2.5". The gap is gone, so every stock is now
held to the same 2e-5 tolerance; what replaces the gap guard is a **coverage** check, because a probe
that silently stopped exercising the measured branch would pass trivially.

Measured after the change, over 2415 probes (161 stocks × 3 channels × 5 densities), driving
`AlgoAddGrain` itself:

```
worst relative disagreement 2.52e-07   (tolerance 2e-05)
worst |amp - 1| at NET density 1.0 = 0.00e+00
13 stocks carry a measured sigma(D) SHAPE and the stage now REACHES it
the stage's hoisted evaluator vs the generated FilmGrainSigma -- worst 2.40e-07
```

**`AlgoCallier.hpp` was staged into this working copy** from the owner's own tree, so the Callier
family runs for the first time here: 11592 probes, worst 1.43e-07. That answers yesterday's review
question with a measurement — the header is not dead code by accident, it is a correct law with no
caller, and now it is at least *audited* while it waits for stage 12b (**C41**, still unopened).
